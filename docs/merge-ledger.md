# Merge ledger

Tracks scope decisions made while turning design docs (the "Brain" round,
then a "final wiring" round) into actual code in this repo.

| # | Decision | Why |
|---|---|---|
| 1 | Built `packages/brain` fully; treated everything else as design | The repo was empty (LICENSE + a 1-line README) when this work started. The design doc references dozens of "prior modules" (module 1-10, Artifacts A/B/C, apps/web, apps/workers, apps/ethics, packages/mcp, packages/agents, packages/knowledge, …) that don't exist anywhere in this repo or this conversation. Fabricating tens of thousands of lines to make those imports resolve would produce code nobody has actually reviewed or specified — worse than being upfront that they're not built yet. |
| 2 | Added minimal `packages/core`, `packages/db`, `packages/skills`, `packages/ethics-crypto` | The three "gap fill" files in the design doc (`skills/types.ts`, `db/client.ts`, `ethics-crypto/retention.ts`) needed real homes with real `package.json`/`tsconfig` to compile at all. Kept each to the minimum surface the Brain and the gap-fill files actually need. |
| 3 | `packages/brain` prisma schema: added `previewFeatures = ["multiSchema"]` + `@@schema("brain")` on every model/enum | Prisma requires both when a datasource declares `schemas = [...]`; the original schema was missing them and would fail `prisma generate`. |
| 4 | Fixed `bus.ts` `xautoclaim` usage | Missing the `"COUNT"` keyword ioredis requires, and read `.messages` off what is actually a positional reply tuple. Left uncorrected, the reclaim path would either throw or silently reclaim nothing. |
| 5 | Defined `worker.ts`'s `ingestState` and `publicStatus()` for real | Both were referenced but never defined in the draft — a straight `ReferenceError` on the first `/healthz` request. |
| 6 | `correlate.ts`: added the missing `emit` import; parse `flowType` out of the JSON payload instead of a truthiness check on the raw string | The original logic (`e.fields.payload ? ... : "UNKNOWN"`) would return "UNKNOWN" for any non-empty payload string, correlation or not — a logic bug beyond the missing import. |
| 7 | Implemented `dedupeAgainstOpen`, `reflex`, `pauseConnector`, `page`, `diagnoseInBackground` for real; stubbed `costDetector`/`freshnessDetector` with an explicit `[]` return and a comment explaining why | These were called in the draft but never defined. Where a real implementation was possible with what's in this repo (dedup query, reflex logging, a PagerDuty-style webhook POST, kicking off the diagnostician), it's implemented. Where it depends on tables that don't exist yet (cost tracking, evidence expiry), it's an honest stub rather than a crash. |
| 8 | `reflexes.ts`/`webhooks.ts` connector-pause and webhook-subscription lookups are pluggable providers, not real lookups | Both depend on a connectors/webhooks data model that isn't part of this consolidation. `setConnectorPauseHandler()` / `setWebhookSubscriptionProvider()` are the intended extension points once those modules land. |
| 9 | `agents/diagnostician.ts` was originally a single-shot RAG call directly against `@anthropic-ai/sdk` — now calls `runAgent()` (see #14) | Superseded by #14 in the "final wiring" round: the shared runtime now owns the model call, JSON-parse-with-repair, and cost/latency logging; `diagnostician.ts` keeps only retrieval and `DiagnosisResult` shape-guarding. |
| 10 | `Anomaly`/`BrainIncident` have no `orgId`; `/v1/brain/anomalies` and `/v1/brain/incidents` are platform-wide, not org-scoped | The draft's MCP scope table claimed org-level visibility for anomalies, which the schema (correctly, in the original design intent — anomalies describe platform subsystems) can't support. Flagged rather than silently mismatched. |
| 11 | `deploy.sh` runs schema setup against the `postgres` service container, not the `api` container | The Node/api image has no `psql` client; the original script would fail at the first `CREATE SCHEMA` step. |
| 12 | `docker-compose.prod.yml` / k8s manifests only define `postgres`, `redis`, `api`, `brain` | `web`, `workers`, `ethics` have no buildable code in this repo — a compose service or Deployment for them would reference a Dockerfile target that doesn't exist and fail on `docker build`. |
| 13 | "Final wiring" round: built the KMS layer, the Brain's SSE stream, and a shared agent runtime for real; skipped the instrumented check runner, the Temporal worker bootstrap, session auth, and the screen-backend handlers | That round's design doc assumed ~150 files from "prior rounds" (the full 65+-model schema, `packages/questionnaire`, `packages/review`, `apps/web`, `apps/workers`, the Check DSL, a User/session domain, …) already existed in this repo. None of them do — only what's listed in this ledger and `docs/architecture.md` exists. Wiring code atop that assumption would just add more broken imports. Built the pieces genuinely self-contained given what's real; documented the rest as a gap rather than faking it. |
| 14 | `packages/core/src/kms.ts`: real AWS KMS envelope encryption (`GenerateDataKey`/`Decrypt`, AES-256-GCM), replacing the "not implemented" placeholder from the Brain round; added `Integration`/`IntegrationType` to `packages/db`'s schema | Completes a stub explicitly left open last round. `storeCredentials`/`decryptCredentials` still take a plain `string` for the integration type (not `@compos/db`'s generated enum) so `packages/skills` stays decoupled from `packages/db`'s generated types — Prisma itself rejects an invalid value at the query. |
| 15 | `packages/brain/src/live.ts`: cross-process SSE fan-out via Redis Pub/Sub, not an in-memory `Map` | The pasted design's `sseRegistry` was an in-process `Map` written to by the worker and read by `apps/api` — but those are two separate containers/processes in this repo's actual deployment (`infra/docker-compose*`), so an in-memory registry in one process is invisible to HTTP clients connected to the other. That would have shipped a live-stream endpoint that silently never emits anything. Redis Pub/Sub (worker `PUBLISH`es after durable ingest, `apps/api`'s `GET /v1/brain/stream` `SUBSCRIBE`s on its own connection) actually crosses the process boundary. |
| 16 | New `packages/agents` (`runAgent()`): only registers `ops_diagnostician`, not the 11-agent registry from the design doc | The other agents (`policy_drafter`, `questionnaire_composer`, `impact_analyst`, …) belong to domains — policies, questionnaires, vendor risk, regulatory change — that have no schema or package in this repo. An `AgentDef` with no caller and no domain model behind it is the same "referenced but never implemented" pattern this ledger exists to catch. Register each as its owning module is actually built. |
| 17 | `runAgent()` is Anthropic-only, no OpenAI fallback | The one real caller (`ops_diagnostician`) only ever used Anthropic; adding a second provider, an `LLM_PRIMARY`/`LLM_FALLBACK` env-var switch, and an `openai` dependency for a code path nothing exercises is speculative surface, not wiring. |
| 18 | `packages/agents` has no dependency on `packages/brain` | `packages/brain/src/agents/diagnostician.ts` depends on `@compos/agents` for `runAgent()`. If `packages/agents` also depended on `@compos/brain` (as the design doc's runtime did, to call `emit()` directly), the two packages would depend on each other. `runAgent()` instead takes an `onTelemetry` callback; `diagnostician.ts` supplies one that calls brain's own `emit()`. One-directional dependency, same telemetry outcome. |
| 19 | Skipped: instrumented check runner, Temporal worker bootstrap, session auth, screen-backend handlers (`handlers/controls.ts`, `handlers/questionnaireReview.ts`) | Each needs a foundation this repo doesn't have — the Check DSL (`evaluateCondition`, `CheckDefinition`), `@temporalio/worker` workflows and an `apps/workers` app, a `User`/session domain with a login flow, and the `Control`/`Evidence`/`Questionnaire`/`Task` schema, respectively. Stubbing the wiring without any of those would produce imports that fail at compile time, not a working feature. |
